# Предположения и вопросы к согласованию

Сделаны там, где ТЗ допускает разумный выбор. Каждый пункт можно изменить без перестройки системы.

## Принятые предположения
1. **Роли** реализованы группами Django: «Техники» и «Администраторы» (+ суперпользователь = администратор).
   Один человек может иметь обе роли.
2. **Назначение администратором не меняет статус**: назначенная заявка остаётся «Новая», пока техник
   не переведёт её в «В работе». «Взять в работу» самим техником сразу ставит «В работе».
3. **Возврат в очередь** (самим техником или админом) всегда ставит статус «Новая» — свободная заявка
   всегда «Новая».
4. «Ожидает» требует комментария; «Выполнена» требует описания выполненных действий и результата.
5. Технику разрешено вернуть в очередь только **свою** заявку (до выполнения). Любой сотрудник службы
   может комментировать любую заявку.
6. **Давно не обновлявшаяся** = открытая заявка без изменений дольше 48 часов (настраивается).
   Обновлением считаются назначение, смена статуса, комментарий.
7. Выбор местоположения — **один список кабинетов, сгруппированный «Здание, Этаж»**, вместо трёх зависимых
   выпадающих списков (проще на телефоне, не требует JavaScript). Если здание не используется, оно просто
   не отображается.
8. Подтверждение заявки показывается на странице `/created/HELP-xxxxxx/`; страница показывает только номер.
9. **Антиспам**: скрытое поле-ловушка + лимит 10 заявок за час с одного IP (кэш в памяти процесса; при
   нескольких процессах Gunicorn лимит применяется на каждый процесс отдельно). За обратным прокси
   IP клиента нужно передавать (см. DEPLOY.md) — иначе все посетители выглядят как один адрес.
10. Максимум 20 позиций оборудования в заявке; количество 1–1000; одна категория — одна строка.
11. Часовой пояс — Asia/Bishkek, язык — русский.
12. Нет личных данных кроме имени, которое вводит сам сотрудник; email/телефон не запрашиваются.

## Нужно согласовать до развития
- Нужны ли уведомления (email, Telegram) и какой канал реально доступен.
- Нужна ли проверка, что открытая форма доступна только из внутренней сети (решается на уровне сети/nginx).
- Нужны ли приоритеты, сроки (SLA), отчёты, вложения, вход сотрудников через корпоративный каталог.
- Политика хранения: сколько лет хранить выполненные заявки и историю.
- Политика паролей и блокировки после неудачных входов (сейчас — стандартные проверки Django, без блокировок).
